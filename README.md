# 储藏库 · Tavern Vault

把 SillyTavern 的聊天楼层收藏到自己选定的电脑文件夹，在酒馆内分类、搜索、阅读原文和打开交互 HTML。

**v0.2.0 是酒馆原生扩展，无需安装酒馆助手。** 保留“哪个聊天的哪一楼”、发言者、消息版本和收藏时间；支持先提取指定标签，再排除指定标签内容。

![储藏库界面](docs/screenshots/library-desktop.png)

## 安装

1. 使用 **SillyTavern 1.19.0 或以上**。此版本下限依据已核对的官方接口；其他版本尚未做真实运行测试。
2. 打开酒馆的“扩展”面板，选择“安装扩展”，粘贴仓库地址：

   ```text
   https://github.com/Morol1225/tavern-vault
   ```

3. 安装后按酒馆提示刷新。点击页面右下方“储藏库”，或扩展设置里的“储藏库 · 打开收藏”。
4. 点击“选择收藏文件夹”，选择一个空文件夹，允许读写。连接旧库时，选择包含 `tavern-vault.json` 和 `items` 的那一层文件夹。

需要**电脑 Chrome/Edge**，通过 `localhost`、本机回环地址或 HTTPS 打开酒馆。普通远程 HTTP、部分手机浏览器或不支持文件夹接口的浏览器无法直接使用此保存方式。文件夹属于运行浏览器的电脑，即使酒馆在云服务器上也一样。

如果用过 v0.1.0 助手脚本，请先停用旧脚本，避免两个入口同时运行。新扩展继续使用同一文件夹格式，不需要转换已有收藏；浏览器需要时重新选择或授权同一文件夹。停用或卸载扩展不会删除收藏文件夹。

## 收藏与筛选

点击聊天楼层旁的“☆ 收藏”。填写标题，选择旧分类，或点“新建分类”。尚未显示的旧楼层也能在储藏库上方的“收藏楼层”里按编号收藏；编号与酒馆显示一致，不需要加一。

收藏栏会实时显示**待保存原文预览**。两个筛选项都可以留空，留空就保存整楼。

| 项目 | 示例 | 效果 |
|---|---|---|
| 只提取这个标签内的内容 | `<content>` 或 `content` | 只保留它包裹的文字，去掉外层提取标签 |
| 再排除这些标签及其内容 | `<image>` 或 `image, thinking` | 从提取结果中删除这些标签和内部内容 |

例如原回复：

```html
其他不收藏的内容
<content>
留下这段故事。
<image>这段图片描述不保存。</image>
继续留下这段对话。
</content>
```

填写提取 `content`、排除 `image` 后，保存的是两段留下的文字。多个同名提取片段用空行连接；标签名不区分大小写，支持配对嵌套。排除多个标签可以用逗号、空格或中文逗号分隔。这里按原文中的字面标签筛选，不会理解剧情语义，也不是 CSS 选择器或正则输入框；页面脚本字符串里出现同样的标签时也需核对预览。

找不到提取标签、标签不配对或筛选后为空时，会提示原因并停止保存。筛选生效后，原文、HTML 页面和显示副本**全部从筛选结果重新生成**，不会复用包含被排除内容的旧快照；来源详情同时记录所用规则。默认标题也随筛选结果更新，手动填写的标题由你保留。

## 浏览与本地文件

左侧选分类，中间搜索标题、正文、聊天来源或发言者，右侧切换“页面 / 原文 / 来源详情”。“整理”能修改标题和分类。收藏是独立副本，原聊天之后改名、删楼或删除，不会改动已保存内容。

刷新时尝试恢复目录入口，需要时点“重新授权”。浏览器无法记住入口时，重新选择同一文件夹即可；正文和分类以磁盘文件为准。完全相同的来源和正文会打开已有记录，避免重复。

```text
你选择的收藏文件夹/
  tavern-vault.json
  items/
    <收藏编号>/
      entry.json
      original.txt
      rendered.html
      pages/
        page-1.html
```

备份时复制整个文件夹。保留根配置和 `entry.json`，仅复制 HTML 无法保留分类和来源。手动改写原文会触发校验并略过该条，插件不会自动删除损坏或未完成的记录。当前没有删除收藏、云同步或 AI 调用功能。

## HTML 的保留范围

HTML/CSS/JavaScript 文本会保留，阅读时在隔离页面中重新执行自身的按钮、折叠、动画等交互；多页面楼层可以切换。原文视图仅显示文本，不执行它。

依赖酒馆实时变量、MVU、发消息、生成、父窗口访问或登录的功能，不会自动获得原聊天环境。远程资源仍需网络，未批量下载为离线资源。运行中的内存、canvas、动态绑定的监听器也无法靠复制 HTML 完整保存。收藏只复制，不重新执行可能改变变量的楼层宏。

没有启用标签筛选时，会尽量保存已显示楼层的外观；尚未显示或无法读取的楼层会用原文生成显示副本。启用筛选时优先确保排除内容不残留，显示副本采用筛选后的原文，不套用原楼层的全部显示处理。

## 代码和私人收藏

这个仓库发布插件代码、合成测试资料和演示截图。**私人收藏不会自动上传 GitHub**；本项目用忽略规则和发布文件白名单排除 `tavern-vault.json`、`items/`、收藏正文、目录入口、本地工具和续接文档。建议把收藏文件夹放在扩展代码目录之外，方便独立备份。

私人 GitHub 仓库也可以使用，但运行酒馆的服务器须已有读取该仓库的 Git 凭据；浏览器登录 GitHub 不会自动授权服务器。只填私人仓库链接不保证安装成功。不要把令牌写进安装地址，服务端可能记录该地址。也可自行下载代码，将包含 `manifest.json` 和 `index.js` 的目录放入自己的 `public/scripts/extensions/third-party/tavern-vault/` 后重启或刷新酒馆。

## 本地维护与验证

需要 Node.js 22 或以上，没有运行依赖：

```powershell
npm run build
npm test
npm run preview
node scripts/check-publish.mjs
```

构建由 `src/` 生成仓库根目录的 `index.js`，酒馆通过 `manifest.json` 加载；使用者从扩展安装器安装后不需要自行构建。`dist/build-manifest.json` 是本地构建摘要，不包含私人收藏。

预览只监听本机，使用合成聊天和内存文件夹，运行实际构建的原生模块，不读取真实聊天或收藏目录。浏览器检查需要自行提供 Playwright 和匹配的 Chromium，路径通过 `TAVERN_VAULT_PLAYWRIGHT`、`PLAYWRIGHT_BROWSERS_PATH` 环境变量设置，运行 `node tests/browser-check.mjs`。

目前通过 **27 项数据/接口检查、14 组浏览器检查**，包括标签筛选、禁用/启用清理、HTML 交互、320/390px 窄窗，以及原生浏览器内部文件读写。**尚未在用户实际酒馆中完成安装、外部文件夹授权和刷新恢复验收。** 详见 [验证报告](docs/验证报告.md) 和 [原生扩展接口说明](docs/native-extension.md)。
